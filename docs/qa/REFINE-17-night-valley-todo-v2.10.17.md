# REFINE-17 · Night Valley 待办工作台重构（v2.10.17）

## 用户问题

用户反馈 Night Valley“待办”页中间文字仍然重叠，界面留白较多，且已完成事项数量增加后无法正常查看和操作；此前记录页修复后还出现过右上角三个原生窗口控件不可用，要求继续保持可检查。

## 根因

旧待办页沿用按截图测量的绝对定位：页面标题、三列、列表和右侧卡片各自依赖固定坐标，窗口尺寸和内容长度变化时没有共同的流布局约束。已完成行仍使用三列隐式网格承载标题、状态、恢复和删除五个元素，操作因此换行到错误的位置；列表也没有自己的可滚动边界。

## 修复

- `src/components/NightValleyViews.tsx` 在现有待办看板内增加今日路径标题、完成进度和行动提示，复用现有待办数据与操作调用链。
- `src/App.css` 为 Night Valley 待办工作区建立文档流网格：顶部摘要、创建入口、三列看板、右侧下一步卡片和底部统计均按区域排布；完成列设置面板内滚动，完成行显式使用标题/状态/恢复/删除的五列布局，并为窄屏增加堆叠断点。
- `tests/app.spec.mjs` 增加 9 条已完成事项的操作对齐/内部滚动断言和 560px 手机视口堆叠断言，同时继续覆盖三项原生窗口控件。

## 验收标准与证据

- 1487×1058 桌面视口：三列不重叠，9 条完成记录在列内滚动，恢复/删除与标题保持同一行，页面无横向溢出。
- 560×860 窄视口：三列和下一步卡片按顺序堆叠，添加入口与完成记录可见，页面无横向溢出。
- 右上角最小化、最大化/还原、关闭控件保持可点击，且不触发顶栏拖拽。
- 本地定向待办/逾期/窗口控件回归：9/9 PASS；Night Valley 尺寸与安全可达性回归：3/3 PASS；完整前端回归：75/75 PASS；`pnpm check`：PASS。
- `pnpm build`（2066 modules）、Rust fmt/check/test（34/34）和 `pnpm package:release` 已通过；三项 Windows 资产的本地大小与 SHA-256 已记录在 `docs/v2.10.17/RELEASE_NOTES.md`，远程 Checks 与 Release digest 待发布闭环后补录。
